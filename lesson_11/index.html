1Less vs Sass/SCSS

Обидва — CSS-препроцесори: додають змінні, вкладеність, міксини та інші можливості поверх звичайного CSS. Ключові відмінності — у синтаксисі, глибині мовних можливостей і процесі компіляції.

Критерій Less Sass / SCSS
Змінні @variable $variable
Синтаксис Один, дуже близький до CSS Два: SCSS (як CSS) і Sass (відступний, без { } і ;)
Логіка Базовий набір можливостей Повноцінне керування потоком: @if, @for, @each
Міксини Будь-який клас можна підключити як міксин — гнучко, але менш явно Явне оголошення @mixin + @include — зрозуміліше й структурованіше
Компіляція JavaScript Dart Sass (сучасний стандарт), раніше — Ruby / LibSass

Один і той самий стиль двома синтаксисами Sass — SCSS (з фігурними дужками) та Sass (відступний, без дужок і крапки з комою):

SCSS

.nav
  ul {
    margin: 0;
  }
  li {
    display: inline-block;

    &:hover {
      background: blue;
    }
  }
}

Sass (indented)

.nav
  ul
    margin: 0
  li
    display: inline-block

    &:hover
      background: blue

2Встановлення та компіляція через Dart Sass

Dart Sass — офіційна сучасна реалізація Sass (Ruby Sass та LibSass давно застаріли). Ставимо через pnpm — він швидший за npm і економніший на диску завдяки спільному кешу пакетів та жорстким лінкам, разом із Node.js. 

# глобально, щоб команда `sass` була доступна в будь-якій папці
pnpm add -g sass

# або тільки в межах проєкту (тоді запускати через pnpm exec sass ...)
pnpm add -D sass

sass --version

На macOS альтернативно можна через Homebrew:

brew install sass/sass/sass

Одноразова компіляція файлу в CSS:

sass sass/main.sass styles.css

Режим спостереження — Sass сам перекомпільовує файл при кожному збереженні: 

sass --watch sass/main.sass:styles.css

За замовчуванням поруч зі styles.css Dart Sass створює ще й файл styles.css.map (source map) та додає в кінець CSS коментар /*# sourceMappingURL=styles.css.map */. Це не помилка: мапа дозволяє браузеру в DevTools показувати, якому саме рядку в .sass-файлі відповідає той чи інший стиль, замість скомпільованого CSS.

Якщо мапа не потрібна — вимкнути її генерацію можна прапорцем --no-source-map: 

sass --no-source-map sass/main.sass styles.css

3Змінні $variable

Оголошуються через $, зберігають кольори, розміри, шрифти. Можна передавати в міксини та функції як параметри. 

$primary-color: #4caf50

.button
  background-color: $primary-color

4Вкладеність та батьківський селектор &

Вкладені правила повторюють структуру HTML, а & посилається на батьківський селектор — зручно для псевдокласів (&:hover) та модифікаторів. 

.nav
  li
    display: inline-block

    &:hover
      background-color: blue

    &:first-child a
      border-radius: 10px 0 0 10px

5@mixin / @include

Міксин групує стилі, що повторюються, і може приймати параметри — так один набір правил підлаштовується під різні елементи. 

@mixin border-radius($radius)
  -webkit-border-radius: $radius
  -moz-border-radius: $radius
  border-radius: $radius

.button
  @include border-radius(3px)
  background-color: blue

6@extend і тихі класи (placeholder %)

@extend дозволяє одному селектору успадкувати стилі іншого, уникаючи дублювання. Якщо базовий клас не потрібен сам по собі в розмітці — його краще оголосити як тихий клас через %: він не потрапить у скомпільований CSS, поки його хоч раз не розширили. 

.btn-basic
  padding: 10px 15px
  border-radius: 4px

.btn-primary
  @extend .btn-basic
  background-color: blue

// тихий клас
%flex-center
  display: flex
  justify-content: center
  align-items: center

.container
  @extend %flex-center

7@function

На відміну від міксина, функція повертає значення (через @return), яке можна одразу підставити у властивість. 

@function calculate-padding($size)
  @return 10px * $size

.container
  padding: calculate-padding(2)
calculate-padding(1)
calculate-padding(2)
calculate-padding(3)

8@for

Цикл, що автоматизує створення схожих класів за числовим шаблоном. 

@for $i from 1 through 5
  .col-#{$i}
    width: 20% * $i
.col-1 → 20%
.col-2 → 40%
.col-3 → 60%
.col-4 → 80%
.col-5 → 100%

9@each

Проходить по списку або мапі ключ: значення й генерує стиль для кожного елемента. Мапа кольорів нижче взята з lib/_colors.sass і потрапила сюди через @forward. 

$colors: (red: #dc2626, green: #16a34a, blue: #2563eb)

@each $name, $hex in $colors
  .text-#{$name}
    color: $hex
.text-red
.text-green
.text-blue
.text-amber
.text-violet

10@if / @else

Умовна логіка на етапі компіляції. Тут міксин themed-button($theme) викликається двічі з різними аргументами — і для кожного виклику Sass одразу вирішує, яку гілку застосувати. 

@mixin themed-button($theme)
  @if $theme == "dark"
    background-color: black
    color: white
  @else
    background-color: white
    color: black

.btn-dark
  @include themed-button("dark")

.btn-light
  @include themed-button("light")

11@import (застарілий підхід)

Класичний спосіб розбити стилі на файли. На відміну від Less, у Sass/SCSS @import також вміє вставляти звичайний .css файл прямо в результат компіляції. 

@import "reset"      // reset.css вставляється як є
@import "variables"  // variables.sass
@import "mixins"     // mixins.sass

.body
  font-family: $primary-font

Sass офіційно визнав @import застарілим: усі змінні, міксини й функції потрапляють в один спільний простір імен, тож легко отримати конфлікт назв між файлами. Сучасна заміна — @use та @forward.

12@use

Підключає файл як окремий простір імен — звертання йде через namespace.$variable або namespace.mixin-name(). Стилі файлу застосовуються лише один раз, навіть якщо на нього роблять @use з кількох місць. 

// _variables.sass
$primary-color: blue

// _mixins.sass
@mixin example-mixin
  color: $primary-color

// main.sass
@use "variables" as vars
@use "mixins"

.body
  @include mixins.example-mixin
  color: vars.$primary-color

Реальна структура файлів цього заняття:

sass/
├── main.sass          @use "variables" as vars
│                       @use "functions" as fn
│                       @use "mixins" as mix
│                       @use "lib" as lib
├── _variables.sass
├── _functions.sass
├── _mixins.sass        @use "variables" as vars
├── _placeholders.sass
└── lib/
    ├── _index.sass     @forward "colors"
    └── _colors.sass

13@forward

Перенаправляє вміст одного файлу далі, не змушуючи споживача звертатись до нього напряму. Так будують "публічний API" бібліотеки стилів. 

// lib/_colors.sass
$colors: (red: #dc2626, green: #16a34a, blue: #2563eb)

// lib/_index.sass
@forward "colors"

// main.sass
@use "lib" as lib

@each $name, $hex in lib.$colors
  .text-#{$name}
    color: $hex

Мапа кольорів у прикладі з @each вище фізично лежить у lib/_colors.sass, а main.sass ніколи не імпортує цей файл напряму — лише lib/_index.sass через @forward.

14@content

Дозволяє передати в міксин блок стилів, який підставляється туди, де в міксині стоїть @content. Класичний приклад — обгортка для медіа-запитів. 

@mixin responsive($breakpoint)
  @media (min-width: $breakpoint)
    @content

.container
  width: 100%

  @include responsive(700px)
    width: 50%

15@at-root

Виводить вкладені стилі на кореневий рівень скомпільованого CSS, навіть якщо в Sass вони написані всередині іншого селектора. Зручно, коли хочеться логічно згрупувати код, але не отримати зайву вкладеність (і зайву специфічність) у результаті. 

.card
  padding: 18px

  @at-root
    .card-badge
      position: absolute
      top: -12px
      right: -12px

Без @at-root селектор .card-badge скомпілювався б у .card .card-badge. З ним — бейдж виходить окремим, "плоским" класом .card-badge, який можна перевикористати будь-де на сторінці:

.at-root-card NEW

Директива Навіщо
$var Змінна: колір, розмір, шрифт тощо
& Посилання на батьківський селектор у вкладеності
@mixin / @include Перевикористовуваний блок стилів з параметрами
@extend Успадкувати стилі іншого селектора
%placeholder "Тихий" клас — існує лише для @extend
@function Обчислення, що повертає значення
@for Цикл за числовим діапазоном
@each Цикл за списком або мапою

@import Застарілий спосіб підключення файлів
@use Сучасне підключення файлу як простору імен
@forward Перенаправлення вмісту файлу далі (публічний API)
@content Вставка блоку стилів, переданого в міксин
@at-root Вивести стиль поза поточною вкладеністю
