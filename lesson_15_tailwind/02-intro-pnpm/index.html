Tailwind, встановлений через pnpm

Встановлено командою pnpm add -D tailwindcss: файли лежать локально у node_modules/tailwindcss, жодного запиту до cdn.tailwindcss.com не робиться. На відміну від Play CDN, який віддає браузеру всі утиліти одним файлом, тут у фінальний CSS потрапляють лише ті класи, що реально використані в HTML — файл виходить значно меншим і придатний для продакшну.

Як це збирається

У реальному проєкті Tailwind не підключають через готовий CDN-скрипт, а описують у власному Sass-файлі трьома директивами, які під час збірки розгортає PostCSS-плагін tailwindcss: 

// sass/tailwind-pnpm.sass
@tailwind base
@tailwind components
@tailwind utilities

А tailwind.config.js вказує, які файли скановані на предмет використаних класів (щоб непотрібні утиліти не потрапили у збірку): 

// tailwind.config.js
module.exports = {
  content: ["./02-intro-pnpm/**/*.html"],
  theme: { extend: {} },
  plugins: [],
};

Gulp прогонює sass/tailwind-pnpm.sass через gulp-sass, а потім через PostCSS-пайплайн [tailwindcss(), autoprefixer()] — так само, як у сусідньому lesson_15_bootstrap компілюється Bootstrap із перевизначеними Sass-змінними: 

pnpm add -D tailwindcss
gulp dev    # компіляція + watch на sass/**/*.sass та 02-intro-pnpm/**/*.html
gulp build  # мінімізована версія для продакшну

CDN vs pnpm + build

Play CDN (01)

  • Один <script>, без збірки
  • Усі утиліти генеруються прямо в браузері
  • Швидкий старт, зручно для навчання й прототипів
  • Не рекомендовано для продакшну

pnpm + gulp (02, ця сторінка)

  • Локальна залежність, працює офлайн
  • У CSS потрапляють лише використані класи
  • Sass дозволяє додати власні змінні/міксини поруч
  • Потребує кроку збірки (gulp dev/build)
