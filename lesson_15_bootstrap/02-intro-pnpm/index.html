Bootstrap, встановлений через pnpm

Встановлено командою pnpm add bootstrap: файли лежать локально у node_modules/bootstrap, жодного запиту до зовнішнього CDN не робиться, сайт працює навіть офлайн. Мінус порівняно з CDN: браузер користувача не зможе взяти вже закешований bootstrap.min.css з іншого сайту — файл довантажиться саме з нашого сервера.

У реальному проєкті з бандлером (Vite, webpack, gulp+sass) Bootstrap зазвичай не лінкують напряму через готовий dist/css/bootstrap.min.css, а імпортують його SCSS у свій sass, наприклад: 

// sass/custom-colors-sass.sass

// 1. спочатку свої значення
$primary: #ff6600
$danger: #e63946

// 2. потім сам Bootstrap — він побачить вже змінені змінні
@import "../node_modules/bootstrap/scss/bootstrap"

Це дозволяє переозначити змінні Bootstrap (кольори, розміри breakpoints тощо) ще до того, як вони будуть скомпільовані у CSS — так, як зроблено нижче на цій сторінці.

Результат: перевизначені $primary і $danger

Це звичайні Bootstrap-компоненти без жодного додаткового CSS:

badge primary

alert-primary — колір узятий із перевизначеного $primary, а не з дефолтного Bootstrap.

Чим це відрізняється від CSS-змінних

Тут не потрібно вручну переозначати --bs-btn-bg, --bs-alert-bg та інші похідні змінні окремо для кожного компонента — Bootstrap сам рахує їх під час компіляції Sass, виходячи з нового $primary. Це "правильний" спосіб зробити власну тему, але він вимагає збірки (pnpm add bootstrap + gulp dev / gulp build), на відміну від точкового патчу поверх CDN (див. 01).
