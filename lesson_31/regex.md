## Чому не варто сліпо довіряти регуляркам від AI

AI пише регулярки швидко, але робить це «на око». Вираз може працювати на прикладі з запиту і помилятися на інших даних.

**Приклад.** Запит до AI: «регулярка для перевірки українського номера телефону». Відповідь:

```js
const phoneRegex = /\d{10}/;

phoneRegex.test(`0931234567`);       // true ✅
phoneRegex.test(`abc0931234567xyz`); // true ❌
phoneRegex.test(`093123456789999`);  // true ❌
```

Тут бракує `^` і `$`. Через це регулярка перевіряє лише те, що десь у рядку є 10 цифр підряд, а не те, що весь рядок і є номером. Виправлений варіант:

```js
const phoneRegex = /^0\d{9}$/;
```

Але й він не прийме `+380931234567` або `093 123 45 67`. AI не знає, які формати потрібні саме вам, якщо про це не сказати.

**Типові проблеми регулярок від AI:**
- немає `^` і `$`, тому вираз знаходить збіг усередині будь-якого рядка;
- вираз занадто суворий і відкидає правильні дані (наприклад, email з `+` або доменом `.travel`);
- вираз занадто м'який і пропускає зайве;
- вираз надто складний: його неможливо прочитати й підтримувати, а іноді він «підвішує» сторінку на довгих рядках.

## Як правильно писати регулярку

1. **Спершу перевірити, чи регулярка взагалі потрібна.** Часто є вбудоване рішення:
   - email — `<input type="email">`;
   - URL — `new URL(str)` у `try/catch`;
   - число — `Number(str)` та `Number.isNaN()`;
   - HTML — `DOMParser`;
   - JSON — `JSON.parse()`.
2. **Описати задачу для AI точно, з прикладами.** Наприклад: «Потрібна регулярка для номера телефону. Правильні варіанти: `0931234567`, `+380931234567`. Неправильні: `12345`, `abc0931234567`. Перевіряти треба весь рядок».
3. **Попросити пояснити кожну частину виразу.** Якщо незрозуміло, що робить якийсь шматок, такий вираз не варто вставляти в код.
4. **Перевірити регулярку на [regex101.com](https://regex101.com)** і на правильних, і на неправильних прикладах. Особливо на граничних випадках: порожній рядок, пробіли, зайві символи на початку й у кінці.
5. **Написати на регулярку тести**, наприклад у Jest, щоб вона не зламалася під час наступних змін:
   ```js
   test(`valid phone`, () => {
     expect(phoneRegex.test(`0931234567`)).toBe(true);
   });

   test(`invalid phone`, () => {
     expect(phoneRegex.test(`abc0931234567`)).toBe(false);
   });
   ```
6. **Тримати регулярку простою.** Краще простий вираз, який зрозуміло читається, ніж «ідеальний» на 200 символів, у якому ніхто не розбереться.
7. **Пам'ятати, що перевірка на фронтенді — лише для зручності користувача.** Її легко обійти, тому дані з форми потрібно перевіряти ще й на сервері.
